# Word broker and single-destination writer implementation plan

This is an engineering plan, not accepted product code or evidence of Word recovery. Read-only source investigation; no product edits, tests, launches or remote writes. CDC remains frozen2.12.1 and schedulers paused. The existing independent transaction SPEC and QUALITY gates are retained. The inspected input is diagnostic3407 plus the 12-file restart-admission proposal bound by product payload b55d7e55c8517e145d776f59299bdde43651d052df23b260196493b7c3f4b1d9. Its current native replacement body still matches diagnostic3407. Root's owned managed writer, not this plan, must perform RED-before-product-application and subsequent validation.

## Outcome and scope

Implement two separately reviewable increments. First move every Word provider wait outside Engine and its message loop while retaining existing native writer semantics and durable admission. Then implement a narrowly supported formatted XML writer with one destination text replacement. Neither increment cancels a blocked Word call or proves Word atomicity. A broker makes switcher/Chrome/UI responsive while Word remains busy; one InsertXML removes our deliberate multi-put prefix sequence, but can itself fail, partially execute or hang with unknown outcome.

Proven facts: execute_pending_correction and execute_pending_selection run under Engine lock; native run_at_generation waits for its STA and teardown; Context::replace performs separately submitted character puts with interleaved refusal points; existing hooks forward ordinary input. Logs show attempted writes then selection-moved/uncertainty, not a proven input cause. The current durable admission addresses lost knowledge across switcher restart, not blocking caller architecture or partial writes.

## Increment1: executable process/protocol design

Use the same signed/build-provenanced g-switcher executable in an explicit --word-broker role, selected before ordinary run/single-instance/first-run UI; this avoids introducing an unrelated standalone binary or running two Engines. The normal process launches once or reconnects to an authenticated existing broker. Broker coordinator has no COM interfaces; a single operation-owned STA performs NativeOM, separate windowless MTA workers perform Word UIA. No parent Engine mutex spans IPC, registry/flush, provider calls, native join or teardown. Client IO and any durable admission discovery/read run on their own bounded worker; no registry may_access call runs under Engine. The IO worker posts an operation-ID result into a bounded mailbox; the message carries a token, not a raw pointer. Engine takes/removes the mailbox record briefly. IPC writes may block only the IO worker.

Authenticate named pipe with current user/logon session DACL, local-only pipe mode, OS-reported endpoint PID and retained handle creation time, expected executable identity/build and a per-broker random session nonce. Validate client identity too. Bound message lengths, counts and field types before allocation; reject remote/unexpected clients. Discovery stores only endpoint/broker identity/nonce, no text. A mutex can establish one live broker instance; abandoned ownership never proves Word provider completion. If broker dies with a Pending marker, do not spawn a replacement that touches that Word birth. A helper kill is not safe cancellation. A new broker may service a genuinely new Word birth only under the existing enrollment/uncertainty protocol and retained global-limit policy. Never automatically close Word or lose unsaved work.

Protocol values:
- Hello(protocol_version, build_id, client_pid/birth, client_nonce) → BrokerIdentity(pid/birth, session_nonce, state).
- Request(op_nonce, client_epoch, kind=Security/SuffixCorrection/SelectedConversion/StoredOriginalUndo, Word_pid/birth, hwnd/thread, runtime_generation, input_seq, policy_epoch, layout, expected_actual/replacement bounded text). Text stays memory/IPC; no diagnostics/durable plaintext.
- Prepared(op_nonce, identity, opaque document/range token, plan_digest, actual original, stage). Document COM identity stays broker-local within the operation; no document names/paths in IPC/logging.
- Permit(op_nonce, stage, plan_digest, client_epoch, generation, input_seq, policy_epoch, focused hwnd/thread/PID/birth, layout). One-use stage permit, not a reusable policy snapshot. Broker independently rechecks fresh Win32 focus/security/protection/document/range and its authenticated shared counters immediately before effectful stages.
- Result(op_nonce, client_epoch, Word_birth, original generation/seq, status=RefusedBeforeEffect/VerifiedSuccess/Uncertain/StillPending, actual original/replacement/range, stage-only evidence). A stale result cannot install Undo/context, change layout or clear another operation. No client message can mark broker operation complete.

One broker transaction slot, no queued mutation backlog. Coalesce not-yet-admitted preparation requests; after durable admission a busy result refuses new Word work. Nested UIA children belong to the same Parent. Pending is flushed before the first Word provider call, including security/WM_NULL where applicable. Child completion occurs only after provider return and all Word-bound interface/apartment teardown. Caller timeout/disconnect/late message does not complete a child. Parent normal completion requires the broker's full verification and children quiescent; native mutation uncertainty/end-Undo/release/CoUninitialize stalls retain Pending. Uncertainty remains even if all threads later return. Idle nonce readback must be exact, as in current guarded candidate.

A new normal client can reconnect but cannot adopt the old client's permission epoch. Disconnect invalidates permission for any not-yet-effectful stage. If already committing, the broker owns conservative verification/Undo closure of that exact operation; parent loss does not issue another text commit, auto-Undo or replay. If successful cleanup independently completes, broker can publish exact nonuncertain completion; if verification needs missing live authority or stalls, remain unknown. Broker restart with Pending never reconstructs success from a timer or unrelated healthy read.

### Input, focus and layout races

Increment input_seq in the low-level hook before forwarding every relevant ordinary key/down-up, mouse/caret invalidation, IME/composition signal and layout/focus/policy change; generation alone currently misses ordinary typing. Publish counters in authenticated shared memory bound to client/broker epoch, with release/acquire ordering. Do not obtain them by synchronously locking Engine from broker. Parent policy epoch increments on pause/app-mode/settings changes; unavailable/disconnected parent fails closed.

Do not create a security-positive token whose exact input_seq must match every future key: ordinary typing would invalidate it immediately; relaxing that constraint creates stale authority. Instead, the Word-specific on_key_event branch records no text/strokes/context while security is unknown and does not reuse a successful security read as permission for later keys. Ordinary keys update counters and, only in Auto mode, post a non-text activity token (identity/generation/input sequence/time only) into the bounded latest-only mailbox. A bounded quiet/debounce observer emits one fresh preparation for the latest activity even when no delimiter has been typed. Delimiter/manual/selected/Undo triggers also enqueue an operation (not text replay), debounce latest-only until keys settle, and broker performs fresh security followed by exact snapshot for that same operation under durable ownership. Derive the candidate token from the fresh Word suffix after security. Preserve Auto prefix/no-delimiter and boundary detection semantics, Manual explicit-action semantics, AppMode::Disabled exclusion, is_code_safe_token and prospective punctuation/prefix filtering, detector/user-word thresholds and bounded MAX_CONTEXT_WORDS context filtering, exact actual-case/paragraph-first-letter normalization, and suffix/delimiter validation. Reconstruct relevant bounded context from the same fresh security-owned document snapshot rather than collecting unverified parent keystrokes. Do not silently replace the detector with a token-only shortcut. Fresh snapshot mapping must have explicit equivalence tests for supported Auto and Manual cases. Actual source/strokes that cannot be reconstructed safely are unsupported and refused; never synthesize legacy SendInput Undo. Delimiter is already delivered to Word, so snapshot checks its exact presence. Security authorization has its own operation-local validity tuple: broker session/client epoch, op nonce, Word PID/birth, HWND/subtree/focus generation, policy epoch, exact metadata request and a bounded freshness deadline. Ordinary input_seq changes alone do not invalidate the pending security response. Password/unknown result denies and reads no candidate text. A successful response is used only inside that exact operation while its security tuple remains current, never as permission for later keys or another operation. After successful security and a bounded quiet point, capture the latest input_seq for the actual text snapshot; require unchanged input counters across snapshot/precommit. Input changes invalidate the candidate snapshot, not retroactively the security response; refuse that correction without automatic new provider retry. Fresh security is revalidated at the existing final native guard boundaries; focus/policy/password uncertainty denies. New keys cause refusal, not permission reuse or replay. This is an explicit Word candidate-acquisition behavioral change requiring its own baseline/runtime tests; simply splitting existing uia_password_state asynchronously is insufficient.

Before each effectful boundary (Undo start, text commit, caret placement, Undo end as appropriate), require exact operation/stage permit and counters plus fresh broker checks. A layout change is itself an effectful operation: perform only as an operation-bound asynchronous phase with current focus/counters, then recheck before text commit; never unconditional late restore after focus moved. Stored-original Undo routes through the same pipeline with expected corrected text and no BlindUndo.

Do not suppress/queue all keys during an unbounded call, use BlockInput or global Word flags. This protocol narrows races; it cannot synchronize arbitrary Word add-ins/IME/mouse/server edits between final check and commit. If input_seq changes during COM commit, postverification may retain uncertainty despite an apparently completed write. No subsequent correction follows that ambiguity. Maintaining responsiveness does not mean every queued keystroke can be safely incorporated into a prior operation.

### NonWord isolation without unowned global focus lookup

A final check before global GetFocusedElement cannot close the focus race: the provider call can access a newly focused Word while no Word marker is owned. Discarding the result afterwards does not repair that ownership breach. Therefore remove global GetFocusedElement from parent generic security, not merely add another precheck.

Use a dedicated nonWord reader and target-bound ElementFromHandle/ElementFromHandleBuildCache for the captured Win32 HWND, with retained process identity and fresh HWND→PID/birth checks before calls. For applications whose actual focused edit is a virtual descendant (Chrome), obtain/validate the focused descendant within that authenticated target subtree; do not substitute root IsPassword=false for the real focused edit and do not fall back to a desktop/global lookup. Every returned element must stay in the expected process/subtree/focus binding; unknown/unsupported element paths deny security and analysis. Actual password/custom-control regression tests must establish equivalent detection before this route ships. Microsoft's API binds ElementFromHandle to the specified window; it does not prove every provider-internal action. HWND reuse/embedded cross-process providers remain explicit limits: mismatch fails closed, and a target-bound path unable to establish its process scope is unsupported. Word-owned dialogs/root/editor all route only to the durable-owned broker. No outside Word UIA call is admitted by a result checked after access.

This structural target binding removes the design's own global-focus choice race. It is not a mathematical guarantee about arbitrary accessibility providers. If target-scoped Chrome/custom-control security cannot be made correct, isolate/deny those unsupported requests rather than quietly restoring unowned global focus lookup. NonWord operations must not reserve a busy Word marker or wait on its reader.

## Increment2: single-destination formatting subset

Microsoft documents WordOpenXML as range-representing XML, InsertXML as replacing text within the destination range, and FormattedText as a Range containing text/formatting. These APIs do not specify all-or-nothing execution, bounded time or byte-identical formatting round trips. Primary references below. Choose WordOpenXML→strict in-memory transformation→one Range.InsertXML call as the prototype, because it needs no clipboard or scratch-document edits. FormattedText requires a separately prepared live Range; a Duplicate is not detached, and editing it edits the source. A scratch document adds focus/style/application-state side effects. Whole-range Text followed by property reapplication introduces multiple effectful operations and cannot prove unchanged mixed formatting. Keep those alternatives out of the first writer.

Implement word_xml_plan.rs as a pure bounded parser/transformer, without fetching entities, DTD/schema/XSLT/relationships or external resources. Start from actual Word-exported packages and define an explicit versioned allowlist, not a generic regex replacement. First subset: one paragraph's plain BMP text runs, equal UTF16 length, no paragraph terminator/control/field/revision/table/drawing/bookmark/comment/content-control/relationship-dependent text. Every original character maps to exactly one original w:t/run; replacement changes only mapped text nodes and required XML escaping. Preserve xml:space and all original non-text nodes/attributes. Reject unsupported style/theme/numbering/dependency cases unless export/import tests prove exact effective formatting and unchanged destination document style scope. Run properties alone are not the effective-format fingerprint. Required package dependencies must be accounted for; if this cannot be done without importing/altering global styles, refuse that package and do not claim the subset is ready.

Fresh NativeOM preparation records exact actual original/case, target range/story/document identity, full surrounding-text contract and effective per-character formatting fingerprint. Read-only formatting reads may remain per-character for initial correctness; optimize only after evidence. Obtain WordOpenXML and require flattened content exactly equal the range text before transform. Revalidate source range/document/formatting and live permit immediately before committing. Mark uncertain before StartCustomRecord. Submit exactly one InsertXML for destination text; never a fallback Text write, per-character commit, retry or auto-rollback. Retain existing protection/story/full-document/generation checks. Then verify exact full expected text, effective formatting per destination character, untouched surroundings/style scope, selection/caret and successful one custom Undo end. On failure/stall at any boundary retain exact Pending/uncertainty. Cleanup/end verification is not proof of atomicity. Both ordinary Word Undo and switcher's stored-original replacement must restore text plus formatting; store an in-memory verified original XML plan with its text/fingerprint when needed, not only old text. Refuse switcher Undo if its fingerprint/document binding is stale.

This subset may refuse common inherited-style documents initially. That is safer than advertising all Word formatting supported. Enable a replacement writer only after actual Word demonstrates the supported subset. It removes the app's deliberate per-character partial-prefix sequence, not every possible partial effect inside Word.

6. Actual installed Word matrix remains mandatory: mixed direct/inherited style/font/size/color/highlight/language boundaries, one ordinary Undo and switcher Undo, paragraph capitalization/delimiters, rapid keys/IME/mouse/add-ins/focus changes, protected/password/track-changes/unsupported structures, hangs during NativeOM/UIA/commit/endUndo/release/CoUninitialize, client restart while provider pending, healthy restart from exact Idle, and continued Chrome/UI responsiveness. ## Auto mode preservation correction

Ordinary-key activity is a non-text Auto trigger, not merely an input invalidation. The bounded quiet latest-only broker path supports correction before a delimiter, including the no-space reported token. Manual/Disabled/code-safe/context/capitalization semantics are explicit regression requirements. Parent stores no Word text or strokes before fresh broker security. This plan change is unexecuted; actual source/runtime fixtures and installed Word acceptance must establish behavior.
