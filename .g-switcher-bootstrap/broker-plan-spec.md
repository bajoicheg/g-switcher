## Three architecture gaps resolved

1. **No persistence waits under Engine.** The corrected entrypoint/process design explicitly forbids parent may_access/registry/mutex/flush/IPC waits under Engine. Fresh Win32 classification plus bounded in-memory mailbox and deny/busy hints only route the request; actual persistent authority is acquired by broker/IO worker. Those cached hints do not grant provider/mutation permission. The production responsiveness seam must also exercise blocked persistence/IPC, not merely blocked NativeOM.

2. **Mandatory target-bound nonWord security.** The plan now removes desktop-global GetFocusedElement from parent generic security rather than merely rechecking focus. Target-HWND ElementFromHandle/BuildCache plus retained process identity binds the root; virtual focused descendants must be resolved inside that exact authenticated subtree. Root IsPassword=false is not accepted for a Chromium focused edit, and unknown/unsupported cases deny without global fallback. Word-owned dialog/editor routes are broker-only. Arbitrary provider internals, HWND reuse and embedded cross-process providers remain explicit limitations; implementation must fail closed on unsupported scope. Actual Chrome password/custom-control regression and the between-routing-and-invocation focus race fixture remain requirements before enabling this API change, not claimed evidence.

3. **Operation-local security avoids input-epoch starvation.** Ordinary Word keys now update counters without storing text/strokes/context or reusing a security-positive cache. Auto-mode ordinary activity submits bounded latest-only non-text tokens, whose quiet observer prepares even without a delimiter; delimiter/manual/selected/Undo triggers also submit an operation, acquire fresh broker security, and obtain the latest safely reconstructable snapshot only afterward at a quiet point. The security response has an operation-local identity/policy/focus/freshness tuple; ordinary input alone does not retroactively invalidate that metadata, but current input_seq binds subsequent text snapshot and commit. Unknown/password results never read candidate text. Nonreconstructable source/strokes are explicitly unsupported rather than synthesized; actual source/context and paragraph-case behavior require tests. Fresh final native security guards remain. No retroactive analysis, reusable mutation positivity, provider retry or legacy SendInput Undo is introduced by the plan.

No remaining architecture blocker is identified for beginning a separately reviewed proposal. Input/IME observation is still an implementation contract: define which composition signals are observable, and refuse unsupported composition rather than claim the hook observes every server edit. Broker-caused layout changes require a new acknowledged stage/counter permit. These acceptance constraints preserve the plan's stated remaining external-input race; no universal transaction guarantee is implied.

## Sound requirements to carry into the proposal

The same executable's early broker role avoids a second Engine. A coordinator without COM, operation-owned NativeOM STA, windowless MTA metadata workers, bounded value-only IPC/mailbox and asynchronous parent continuations can isolate client waits. Main Engine never joins/waits on broker/native/provider work. Every production security/correction/selection/Undo route and public/test helper must be audited; nonnative Word dialog controls retain refusal rather than generic fallback.

OS pipe endpoint PID/creation identity, current-user/logon-session ACL, local-only mode, build identity and nonce-bound handshake are appropriate admission requirements. Precisely define singleton/discovery collision and stale endpoint behavior in implementation: only the authenticated live broker owns one transaction slot; an abandoned mutex or disconnected client never clears Pending. No queued mutation backlog, replacement provider/writer, timer recovery, helper kill as cancellation, or automatic Word closure. Older unguarded clients and same-user registry tampering remain outside this cooperative protocol's protection.

Durable Parent covers first Word provider call through native verification, end Undo and interface/apartment teardown; exact children survive caller timeout and cannot clear native uncertainty. Read-only late completion may release its exact ticket, but unknown mutation remains sticky. Broker death with Pending denies the same Word incarnation. New client epoch cannot inherit old permission; stale reply cannot install context/Undo/layout or complete ownership. Any continuation requiring unavailable live authority refuses. A genuine new Word birth plus enrollment can be admitted conservatively; existing global limitation remains documented.

Shared input/policy counters avoid reentrant Engine locking, and one-use stage permits narrow stale-work races without claiming transactional Word input exclusion. Define legitimate layout-phase acknowledgement/new counters before the next stage: a broker-caused layout event must not silently reuse the old permit or blindly restore after focus changes. EndCustomRecord cleanup must never be replaced by blind Undo; missing authority retains uncertainty rather than submitting new text.

Baseline must enter one blocking provider and actually prevent a posted nonWord event; fixed production seam must process that event while provider remains blocked, retain Pending across client restart, and demonstrate no replacement entry. Include broker bootstrap/persistence/IPC backpressure/teardown stalls, stale or spoofed authority, duplicate tickets, and identity changes. Observed compiled named failing test must precede applying production files; exact production module integration and nonzero named GREEN cases must follow. Full typed Windows/Clippy/26 gates remain necessary, without substituting mocks for Word acceptance.

Ship broker containment independently from XML. It retains the existing per-character mutation and its possible first partial result; it primarily changes responsiveness and ownership across client loss. XML is a later restricted experiment whose effective-format/style-scope round trips, one Word Undo and stored-original formatted Undo must be proven before enabling a writer. One InsertXML may still fail partially or hang; no single COM call or client kill guarantees atomicity/recovery. Refusal outside the verified formatting subset is an acceptable outcome. Actual Word matrix is an enablement/behavior gate, not a condition for completing this read-only plan.
