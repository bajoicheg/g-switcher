# CDC owner policy: active execution contract

This is the compact canonical entry for every CDC project. The exact detailed clauses remain binding in [cdc-owner-working-policy.details.md](cdc-owner-working-policy.details.md); consult only the relevant section when the task depends on it. Explicit current owner instructions take precedence. Operator: @bbajoi.

- Complete authorized useful work autonomously. Do not ask again for authorization already given. Preserve native goals, budgets, deadlines, Source/role/provider and actual permissions; never infer a new autonomous window. A denial forbids retrying the effect through another route or worker.
- Preserve original IDs, UNKNOWN, failed outcomes, guards, claims, reservations, spent and append-only history. Never infer success, refund spend, reset quotas or replay an uncertain effect. Reconcile once using available evidence; block only the dependent effect when a dangerous duplicate cannot be excluded.
- Kimi disabled. Fleet, Gemini, retired Supervisor and paused schedulers stay disabled unless explicitly authorized. Do not move credentials under a running worker, change accounts or enable paid fallback. Keep secrets out of output, artifacts and Git. Cloud access uses the existing authorized route; details §Codex Cloud apply only to Cloud work.
- One executor owns a complete dependent pipeline through checks, Source publication, application and result. Use additional executors only for genuinely independent implementation with separate state, bounded fresh context and one final handoff. No reviewer models, status-only workers, coordination chatter, repeated acceptance/FULL/login/probes or model polling. Three useful streams are an option when independent work and resources justify them, never a quota.
- Read the active checkpoint/task and directly relevant facts only. Completed work stays as references. Do not reload full policies, README, old chats, images, logs or the context index. For service work read only the matching service_context. Use rg and bounded file windows; explicitly cap routine tool output at 1200 tokens. Preserve full original evidence on disk, without duplicating it into reports. Do not change the compaction threshold; a summary is at most 600 words.
- Batch independent reads; run dependent preparation, relevant checks, publication, application and receipt as one process pipeline. The process waits for terminal; the model resumes only for a terminal result or actionable blocker. A service ACK needs zero or one tool round, never a new project entry or separate acceptance.
- Immutable SDKs are replaced through published qualified packages. Operator fixes, registered Source, native success, canonical release and consumer adoption are separate facts. Windows/Cloud/GUI adoption remains UNKNOWN without evidence. Windows CI only for a ready candidate; no paid overage.
- Every substantive Russian report uses fresh Europe/Moscow time: [HH:MM DD.MM], then 🟢 applied improvement, 🔴 failure or 🟡 important status. Telegram uses one brief task card; technical IDs, paths and history belong in Technical data. Route prompts, approvals, controls and documents to the selected project/chat, preserving one-use decisions and effect identity. Transport/status polling uses no model.
- Account once at closeout from native response IDs, including compaction, workers and the final answer. Cached tokens are a subset of input; report new input, cache and output separately. Never estimate unknown money as fact. Keep original spent; use the existing local final-response tail collector, no accounting polling.

Detailed clauses, recovery procedures and Telegram delivery rules are preserved verbatim in the linked reference; they are not new goals or permission grants.
