# G-switcher 2.0.1 — короткая проверка Edge и Chrome

Это проверка кандидата, а не разрешение на публичный релиз. Сейчас нужны только два браузера. Word/Excel и остальные приложения — отдельный последующий этап; не заполняйте их результатами PASS без проверки.

## Подготовка

Закройте прежний G-switcher через трей. Распакуйте новый комплект в отдельную папку. Не смешивайте EXE и инструкции из разных сборок. Сохраните `BUILD_PROVENANCE.txt` и `SHA256SUMS.txt`: они связывают результат с конкретным коммитом и бинарными файлами.

Запустите `g-switcher.exe` обычным пользователем, без повышения прав. При предупреждении Defender/SmartScreen не отключайте защиту и не добавляйте исключение: сохраните точное сообщение для разбора.

В каждом браузере обычным способом откройте файл `manual-browser-test-2.0.1.html` из комплекта. Не используйте специальные параметры запуска браузера или расширения. Страница локальная, без JavaScript и внешних ресурсов. Проверьте, что G-switcher не поставлен на паузу, а процесс браузера не находится в Disabled.

## Сценарии — отдельно в Edge, затем в Chrome

| Проверка | Действие | Ожидаемый результат |
|---|---|---|
| Auto | В режиме Auto и английской раскладке напечатайте `ghbdtn ` в поле автоматической проверки; пробел обязателен. | `привет `; соседний текст не изменился. |
| Undo после Auto | Сразу после исправления нажмите `Ctrl+Backspace`. | Ровно `ghbdtn ` и исходная английская раскладка. |
| Manual | Установите для браузера Manual only. В поле ручной проверки напечатайте `ghbdtn` без пробела и нажмите `Ctrl+Shift+F12`. | `привет`. Сразу `Ctrl+Backspace` возвращает `ghbdtn` и английскую раскладку. |
| Selected / textarea | В многострочном поле уже есть подготовленная строка `LEFT \| ghbdtn rfr ltkf \| RIGHT`. Выделите только `ghbdtn rfr ltkf`, нажмите `Ctrl+Shift+F9`. | `LEFT \| привет как дела \| RIGHT`. `Ctrl+Backspace` возвращает исходную строку; соседние `LEFT \| ` и ` \| RIGHT` не меняются. |
| Фокус и каретка | В режиме Auto начните `ghbdtn` в поле A и до завершающего пробела перейдите в поле B. Отдельно повторите, переместив каретку стрелкой/мышью. | Нет отложенной коррекции не в том месте; текст обоих полей остаётся целым. |
| Password | Только в локальное тестовое password-поле введите фиктивное `ghbdtn123`. Попробуйте обычный ввод и сочетания конвертации. | G-switcher сам не меняет тестовый пароль и не переключает раскладку в результате коррекции. Ничего не делает — здесь это PASS. Не вводите реальные пароли, PIN или коды. |
| Pause | Включите Pause через `Ctrl+Shift+F11`, введите `ghbdtn `; затем снимите Pause и повторите в новом поле. | На паузе исходный текст сохранён; после возобновления новые слова снова исправляются. |

После проверки верните процесс браузера из Manual only в Auto. В таблице указаны стандартные сочетания клавиш; при изменённых настройках используйте фактически назначенные сочетания.

## Как сообщить результат

Для этого короткого прогона можно ответить прямо в чате, без запуска полного recorder:

```text
CI / commit: из BUILD_PROVENANCE.txt
Windows build: из winver
Edge, версия ...: Auto ..., Manual ..., Selected ..., Undo ..., Password ..., Focus/caret ..., Pause ...
Chrome, версия ...: Auto ..., Manual ..., Selected ..., Undo ..., Password ..., Focus/caret ..., Pause ...
```

Не ставьте PASS заранее. Когда обычное поле браузера оставляет `ghbdtn` неизменным, это незавершённая поддержка, а не успешная проверка функции. Опишите точное действие и фактический результат. Если текст повреждён, прекратите тест в этом поле и сохраните пример/скриншот.

Полный recorder `g-switcher-compatibility.exe record` и валидатор `g-switcher-compatibility.exe verify` предназначены для всей матрицы релиза. Они не требуют выполнения PowerShell-скриптов. Короткая проверка браузеров не заменяет полную матрицу и не разблокирует публикацию автоматически.

## Граница автоматической проверки

Браузерный CI проверяет настоящий UI Automation-адаптер Edge/Chrome: изменение input и textarea, восстановление текста, выделение, различение DOM-полей и обнаружение password-поля. Он использует специальные параметры accessibility для детерминированности и не является сквозным тестом клавиатурного hook-пути в обычном запуске браузера. Поэтому сценарии выше нужны отдельно. Результат для простых input/textarea нельзя автоматически переносить на произвольные contenteditable-редакторы, Word PWA и сложные веб-приложения.
