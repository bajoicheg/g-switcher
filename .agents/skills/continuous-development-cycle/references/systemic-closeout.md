# Current native reporting and systemic closeout

## Reporting and RCA

Capture each substantive report with reporting_contract.capture, then emit it at
that boundary. command_timestamp renders the actual current runtime clock, not
an inferred elapsed minute or the original command's timestamp. Russian body,
Moscow [HH:MM DD.MM], no suffix/seconds; completed logical operation duration is
rounded whole minutes and unknown tokens are omitted. This package contract
qualifies its supported paths, not arbitrary host chat or provider behavior.

Current execution-continuity/v2, managed-host-finish/v2, continuation-cycle/v2,
final_response_gate and cdc closeout require the invocation's canonical reporting
inventory. Its derived dedicated Git document ref uses the configured original
lease endpoint, exact original owned revision, invocation/owner/generation and
checkpoint. Material anomaly facts/history are preserved. Every admitted/open,
implementing or explicitly deferred item stays visible in the report. Diagnosis
or proposal is not admission. A fix key reinforces its existing durable backlog.
Claimed resolution needs an authoritative Git verification receipt, exact
correction commit/root and rehashed raw command stdout/stderr/returncode/interval;
a saved label, caller bool or digest string alone cannot qualify it. A receipt
proves only its recorded scope; local regression is not hosted CI or deployment.

Managed finish is a preparatory release/worker boundary: managed_finish_allowed
is not owner-final permission, and final_response_allowed remains false while
the original controller must exit. Current final-response-gate/v2 requires the
original handle and a live package-owned VerifiedTerminalProof issued after
controller physical closure; serialized/copied proof or caller bool is not
authority. It revalidates actual lease/pool/runtime/birth/absence at every use.

A resumed finish reauthenticates current canonical inventory before publication
and final permission; it does not trust local session/cache booleans. Historical
v1 records remain readable for auditing, not current final-response permission.
continuation_cycle with current native reporting emits the report and recommends
next action; even a COMPLETE label requires native closeout, not final authority.

## Receiving writer admission

receiving_ci_preflight.prepare_admission runs before a fresh managed delivery
writer at a released/unowned/reconciled boundary. Pin the verified canonical
release and actual installed package/lock, adapter/checkpoint controls and budgets.
Use the existing official gh read-only API or original supported connector GET
receipts committed through the existing owned control protocol. Native Git joins
independently check source, default and PR bases. Arbitrary JSON/URLs/booleans do
not provide admission. Do not create a new transport, token or orchestrator.

Inspect the stock prepare API, existing-branch push two-dot and cumulative PR
three-dot paths including prior PR changes, PR-target base definitions and
workflow_run default-branch definitions/upstream branch filters. GitHub.com
path-filter coverage is capped at3000 files; >1000 pushed commits or incomplete
diff requires conservative receiving admission/provider reconciliation. At most
three workflow_run chaining levels; conclusions/job expressions are provider
results, never inferred GREEN. Unsupported filters fail closed. New-branch diff
or timeout coverage must be reconciled explicitly, not reported as an exact skip.

Prospectively reserve the necessary automatic receiving cycle on actual canonical
budget before writer admission. ReceivingPreflight.admit reads back that exact
unconsumed charge; it does not grant a launch capability. Pass ReceivingAdmission
to the genuine managed start and GitReleaseDelivery. Stock prepare binds one real
candidate, claim and assembly to the cycle through guarded canonical CAS. Original
prepared/submitted/UNKNOWN SHA/message/claim/manifest cannot be rebound. A refreshed
same-permission provider read can update current observation, never original
identity. Drift blocks the affected effect; no replay/replacement grant or waiver.
Lost reply reconciles the same candidate/claim, not another publication.

## Detached result and physical closeout

managed_executor_pool.preview_writer_result derives actual root/package and both
net/full-history path sets before assigned branch adoption. It confers no launch,
completion or publication permission. Completed result still requires the assigned
branch's exact HEAD and full-history scope, rejecting hidden intermediate writes.

terminal-bundle/v2 binds original handle_root/handle_id to the actual canonical
lease endpoint and original issued terminal-capability/hold/owned/release chain.
Runtime verify_terminal rechecks original Git pool claim and waitpid ECHILD
quiescence, exact boot and process births, accepted/integrated result and fresh
physical absence of worker/supervisor/controller. Wrapper exit or supplied
absent=true is insufficient. Unknown historical births stay UNKNOWN. Zombie
presence is not absence. Preserve actual raw exit stdout/stderr/returncode before
interpretation; physical absence alone does not invent controller exit0.

Source release, hosted checkout, installed/personal state, product deployment and
final Root acceptance stay distinct. Schedulers remain paused absent explicit
separate authorization.
