# Quality levels and reuse

Use this contract only after explicit project policy migration. `quality.default_level` is FAST, MEDIUM or FULL; `quality.max_validation_cycles` defaults to 2 in the new template. Missing settings preserve legacy review and validation requirements. Changing the policy changes its digest: advance the policy revision and reconcile the checkpoint through normal migration.

FAST requires targeted behavior/result checks and executor self-review. MEDIUM requires affected tests/regressions, necessary build and one independent combined review covering requirements and quality. FULL requires all applicable validation and separate ordered independent requirements/quality reviews. Core CDC, executor authority, authentication, AD writes and dangerous migrations require FULL. Effective level is the maximum of project level, declared risk level and category floor. Independent review validates category/coverage against the actual diff; the helper cannot discover hidden risks or authenticate supplied observations.

Adapter settings, risk input, mandatory checks and budgets must come from the authenticated current project policy and scoped change. Do not reduce a project's explicit default without an authorized policy change. Do not use FAST wording to conceal an ordinary feature or critical path. Unknown risks require investigation. All product, platform, release, ownership and explicit owner conditions remain mandatory regardless of level. A portable Windows release still needs its required Windows evidence.

Use quality-assessment/v1 -> review-pipeline/v2 -> branch-finish/v2 for an explicitly migrated task. v1 records preserve existing semantics. Bind the review to the immutable candidate in branch finishing; open findings block every level. Reviewer identities and their artifacts must be genuine independent observations, not invented labels. Results grant no write, external-start, merge, release, scheduler or budget authority.

Evidence-reuse/v1 binds the original candidate and command observation to the proposed target, exact dependencies, argv, parameters, environment and test definition. Coverage refs are independently reviewed dependency coverage, not a claim that an arbitrary subset is complete. Include configuration, generated inputs, test files, runtime/toolchain and relevant platform/external-state dependencies. Missing coverage means rerun or establish coverage; never guess equivalence. The original run must be freshly resolved/authenticated from source_evidence_ref. Any changed input or non-success result invalidates reuse. An exact-final-candidate rule sets exact_candidate_required=true; a supplied false flag cannot override project/release policy.

Current HEAD, authority, lease, external guard and checkpoint observations remain fresh action-bound checks. Reused results are not new runs: keep both SHAs and source evidence. Adopt a previously verified unchanged package with exact installation and compatibility checks; rerun the full package suite only if relevant inputs changed or existing proof does not cover the need. Document/report changes do not rerun unrelated product checks unless they affect execution inputs or packaging.

Validation-cycle/v1 records cycle number, concrete changes, risk, why old evidence is insufficient, strategy revision and measured time/tokens/external starts with configured limits. Unavailable measurements are null with a reason. Cycle 1 is initial validation, cycle 2 follows a correction. Subsequent cycles require a referenced strategy revision; no automatic repeat, budget reset or mandatory-check waiver. Existing external-start reservations/limits remain separately enforced. Record the effective level, proofs, commands, budget and next action using existing checkpoint/continuation evidence refs; do not extend checkpoint schema informally.

Compare elapsed time, available tokens and rework per accepted functional improvement on upcoming tasks. Do not fabricate savings, repeat a finished rollout as a benchmark, or bypass an occupied product owner to collect measurements.
