# Administrative retirement of an UNKNOWN isolated Git submission

## Separate Actions administrative quarantine (3.5.1)

The exact taskless `ordinary-unsigned-pilot` / `github-actions` workflow-dispatch
can be administratively quarantined after explicit owner disposition. UI Close
without Run is original evidence, not a cancellation barrier. Missing transport
barrier, dispatcher birth and no-in-flight proof stay NULL; outcome stays UNKNOWN
forever. Positive `submission_recovery` is unchanged and must reject this case.

Use only the original native channel. Authenticate exact original immutable
guard/claim/released lease history, UI and owner decision, and actual workflow
bytes at the original candidate. Workflow/job permissions must remain read-only.
Obtain complete status/check-runs/Actions pages for the exact original operation,
workflow/candidate/claim window, with actual raw response references and complete
pagination. Observe the exact original executor/supervisor identities and births
in their original kernel; establish physical absence and no pending local writes.
A missing original executor birth/kernel or incomplete provider lookup remains a
blocker. Missing *dispatcher* proof is recorded separately as UNKNOWN.

Save and independently read back those genuine reports in the existing original
checkpoint/control history. Deployment `trusted_evidence_pins` must come from
independently authenticated original-channel configuration, never by copying an
untrusted caller proof. `authenticate_actions_retirement` uses the actual configured
Git lease store, authoritative ancestry, exact regular blob bytes/SHA256, and
native PID absence; JSON/reference syntax or a caller bool cannot issue authority.
An `ActionsRetirementEvidence` capability is bound to the exact store/revision,
proposal and evidence. `retire_actions_unknown_cas` requires it; raw coordination
CAS cannot append Actions quarantine. Native caller authentication still owns
truthful provider lookup and out-of-band owner authority: this API does not send
provider requests, infer a provider result, or authenticate a person from JSON.

The one canonical transition changes only external_guard and appends one
`actions-submission-retirement/v1` entry to existing submission_retirements.
Original guard/release and all other historical/control/budget fields survive.
No submission, takeover, merge or release permission is granted. Original key,
claim and same-candidate external rearm fail closed under attempt/ref/mode/backend
disguises. Fresh genuinely unrelated native compute/control/security source writes
remain available through the existing managed product_write path without arming
an external operation on that retired candidate. They still need independent
ownership/budgets and cannot dispatch the retired workflow.

After lost CAS reply use `observe_actions_retirement` to read the exact same
authoritative entry; never repeat CAS/send. GAD raw controls remain private in its
original native channel; public CDC tests use anonymized local Git fixtures only.
This patch release does not apply a GAD transition or authorize a new pilot.

## Existing isolated Git retirement (unchanged)

An absent pilot ref, empty Actions list, elapsed time or different boot never prove Git rejection. Terminal reconciliation still requires real provider evidence.

When the owner explicitly accepts preserving UNKNOWN without replay, `scripts/submission_retirement.py` supports exactly one narrow administrative transition. Authenticate original immutable caller/effect observations: one returned Git receive-pack invocation, create-only empty destination under refs/heads/pilot/, exact candidate, and original executor physically stopped with no pending shared writes. Bind current released v2 lease revision/digest, original guard and immutable owner decision. Persist the proof in the existing durable checkpoint and independently read it back before `retire_unknown_cas`.

The canonical expected-revision CAS moves the unchanged guard to append-only submission_retirements, outcome UNKNOWN and replay_forbidden true. It preserves claims, terminal facts, resolutions, release and generation; its helper invokes no provider. A lost CAS response requires reading the actual state, never repeating a submission. A retired candidate cannot be rearmed under new identity/binding. Never delete/recreate the pilot or refund the original budget. Ordinary unrelated new candidates still require fresh managed ownership, budgets, intent and one-use dispatch checks.

The evidence parser does not authenticate its producer. Release under CDC3.3.1 and verify its actual bytes before live application; older runtimes reject the optional new history field. Preserve original product validation blockers and checkpoints; upgrade only the independent CDC package scope. Accepted/taskful effects and arbitrary Git/source/release mutations are unsupported.

### Legacy Actions intake (synthetic correction draft; not yet released)

The Actions administrative route may preserve an unrecorded original executor
birth as null while observing the exact original supervisor as a stopped zombie.
It must not call that supervisor absent. The original native request, terminal
receipt and owned-marker chain, exact worker IDs and recorded births must be
archived by the original channel and independently pinned by its trusted
configuration. Local files alone are not signed or immutable Git evidence.
The capability authenticates the pinned bytes and original released ownership,
then rechecks the original boot, known supervisor birth/state, no descendants
and absence of the original registry workers before the conditional write.
Any live or substituted worker, supervisor birth mismatch or unbound registry
fails closed. UNKNOWN transport and missing dispatcher proof remain unchanged.

Legacy UI records retain all raw fields, including incidental push observations.
A declared legacy-ui/v1 normalization reads only the authenticated original
submitted/form_closed/time observation, retaining an unrecorded final-click
fact as unknown. It supplies no transport barrier or provider terminal result.
Pins can identify a byte range inside an immutable original blob; both the
whole-blob and exact selected-range digests are checked before JSON extraction.
Numeric workflow environments require an independently pinned provider mapping
of workflow ID, filename, repository and exact candidate. A push run can supply
that mapping only, never the terminal result of the guarded dispatch attempt.


Historical legacy launch binding additionally requires the exact pinned request,
receipt, terminal hold intent and owned marker. A deterministic historical
capability descriptor may be reconstructed from these original records and
authoritative original owned lease/pool revisions only when its canonical hash
matches the original capability_ref and its invocation hash binds the exact
launch task, attempt and request digest. It is never a newly minted sealed
capability or new launch permission. Native authentication and CAS revalidation
read the actual owned revision and both original claim/capability pool revisions
from the configured endpoint, verify ancestry and the exact running attempt,
and reject mixed prior-attempt or released/unrelated ownership records. Missing
original fields remain missing and fail closed; private original-host intake is
evaluated later against this qualified public contract.

The separate claim-null source publication and prelaunch intake protocols are
documented in [Native UNKNOWN recovery](native-unknown-recovery.md). They issue
distinct administrative capabilities and preserve original UNKNOWN liabilities.
